# プロバイダーへの実行振り分け

pstack のモデル選択には、プロバイダーを明示した記述子を使う。

```text
<provider>:<model>@<effort>
```

## モデル対応表

| 系列 | 上流 pstack の選択値 | プロバイダー | モデル | 既定の推論強度 | 選択可能な推論強度 | Claude ネイティブエージェントの語幹 |
|---|---|---|---|---|---|---|
| fable | fable | claude | fable | max | low medium high xhigh max | fable |
| sol | gpt-5.6-sol-max | codex | gpt-5.6-sol | max | low medium high xhigh max | - |
| grok | grok-4.6-fast-xhigh | grok | grok-4.6 | xhigh | low medium high xhigh max | - |
| opus | opus | claude | opus | xhigh | low medium high xhigh max | opus |

許可する推論強度は `low`、`medium`、`high`、`xhigh`、`max` のみである。初回実行では、各行の「既定の推論強度」を要求する。Claude ネイティブエージェントの語幹が `-` なら、その系列に Claude ネイティブエージェントはない。それ以外の同梱エージェント名は `pstack-<stem>-<effort>` である。

`fable` と `opus` は Claude Code の更新追従型の別名である。Claude は各別名を、その系列の利用可能な最新リビジョンに解決する。ランナーの実行証跡は、要求した別名を `model` に、プロバイダーが報告した具体的なリビジョンを `reportedModel` に保存する。検証で受け入れるのは、要求した系列に一致する、数値のリビジョンを持つ `claude-fable-*` または `claude-opus-*` だけである。

## 読み込み時の正規化

対応表との照合や経路選択の前に、設定済み記述子を正規化する。プロバイダー付き Claude モデルが `claude-fable-` または `claude-opus-` で始まり、残りのリビジョン部分が数字とハイフンだけなら、メモリ上でモデル部分を `fable` または `opus` に置き換える。プロバイダー、推論強度、役割、作業枠の順序は保つ。ネイティブ起動やランナーの argv には、正規化済み記述子だけを使う。バージョン付きの旧モデル名を Claude に渡してはならない。

この読み込み時の規則により、古い設定表がインストールされていても、ユーザーファイルを書き換えず、すぐに系列の最新リビジョンを使える。親の実行ごとに 1 回、保存された設定表が古いことと、`/setup-pstack` が通常の動作確認と承認の後に書き換えることを報告する。未知のバージョン付き Claude モデルは引き続き無効である。外部ランナーは、正規化を逃れた Fable や Opus のバージョン固定を黙って実行せず拒否する。

`fast` は Cursor の Grok 選択値の一部であり、Grok Build CLI のモデルや推論強度のフラグではない。移植可能な Grok の経路では、現在の CLI モデル `grok-4.6` に固定する。初回の Grok の推論強度は `xhigh` である。

## 実行経路は親が管理する

最上位の実行環境が経路を 1 回だけ決める。子には、プロバイダー、モデル、推論強度、アクセスモード、プロンプト、作業ディレクトリ、出力パスを割り当てて渡す。子が実行環境を検出し、プロバイダーを選び、別モデルを起動することはない。環境を示すマーカーは、並列展開前に最上位の実行環境を確かめる補助にはなる。ただし、入れ子のプロセスは親のマーカーを継承するため、それを経路選択に使ってはならない。

| 親 | `claude:*` | `codex:*` | `grok:*` |
|---|---|---|---|
| Claude Code | ネイティブの `Agent` | 外部ランナー | 外部ランナー |
| Codex | 外部ランナー | ネイティブの `spawn_agent` | 外部ランナー |

`inherit-parent` と `auto` は別名として残す。親のネイティブなサブエージェント機能を通じて、親の現在のモデルと推論強度を使う。パネルでは依然として 1 作業枠を使うが、プロバイダーの多様性は減る。その旨を総合結果の記録に書く。

## ネイティブ実行の作業枠

ネイティブ起動なら、2 つ目の CLI の起動と、その基本コンテキストを省ける。

- Claude Code では、記述子の `(provider, model)` をモデル対応表の 1 行に照合する。その行の Claude ネイティブエージェントの語幹と、記述子の推論強度を使い、`pstack-<stem>-<effort>` 経由で起動する。これらの定義は、更新追従型のモデル別名、要求された推論強度、`background: true` を選ぶ。`pstack-fable-max` と `pstack-opus-xhigh` もこの集合に含む。完全なタスク、根拠となるファイルパス、アクセスモード、固有の出力先を `Agent` のプロンプトに渡す。タスクハンドルを保持し、すべての並列起動を終えてから結果を回収する。
- Codex では、記述子のモデルと `reasoning_effort`、完全なタスク、根拠となるファイルパス、アクセスモード、固有の出力先を指定して `spawn_agent` を呼ぶ。書き込み担当者には隔離した worktree を使う。Codex のサブエージェントはもともと並行して動く。

親と同じプロバイダーの記述子を外部ランナーへ送らない。ネイティブ経路のほうが低コストで、すでに使えるため、外部ランナーはその呼び出しを拒否する。

## 外部実行の作業枠

ランチャーは、インストール済みプラグインの `skills/poteto-mode/scripts/runner/pstack-runner` にある。親は候補への完全なプロンプトを固有ファイルに書き、固有の出力ディレクトリまたは worktree を作り、ランチャーを直接呼ぶ。その前に別のエージェントを挟まない。

```text
pstack-runner \
  --parent <claude|codex> \
  --provider <claude|codex|grok> \
  --model <real CLI model> \
  --effort <low|medium|high|xhigh|max> \
  --mode <read-only|isolated-write> \
  --prompt <unique prompt file> \
  --cwd <repository or dedicated worktree> \
  --output <unique final-response file> \
  --receipt <unique receipt file> \
  [--timeout <seconds>]
```

引数は argv 配列で渡すか、すべてのパスを引用符で囲む。プロンプト本文をシェルコマンドに埋め込んではならない。ランチャーは割り当てられた CLI と認証を事前確認し、モデルを正確に 1 回呼び出す。CLI が対応していれば、再帰的なエージェントと環境からの暗黙のスキル起動を無効にし、組み込みツールの利用範囲を制限し、正確な provider/model/effort フラグを記録する。外部作業枠には親の MCP 機能を渡さない。MCP に依存する Why と Reflect の役割は `inherit-parent` または `auto` に保つ。ランチャーは代替経路へ切り替えない。

Grok の認証事前確認は、1 回だけ再試行する。最初の `grok models` の結果が未認証と判定される場合、ランナーは 5 秒待ち、同じ事前確認をもう一度行う。2 回目も失敗したら終了する。待機と 2 回目の試行は、ランナー全体の絶対期限とキャンセル状態を共有し、証跡には両方の試行の根拠を残す。モデル実行そのものは再試行しない。

契約済みの子 CLI が認証情報やネットワークに到達できるかどうかは、引き続き親ツールのサンドボックスが決める。セットアップのライブ動作確認は、実際の親のプロファイルから実行する。外部 CLI がブロックされたら、明示的な脱落として扱う。権限を上げたり、黙ってモデルを代替したりする理由にはならない。

親からの呼び出し自体も、再開可能なバックグラウンド処理でなければならない。

- Claude Code では、`run_in_background: true` を指定した Bash ツールでランチャーを呼び、タスク ID を保持する。フォアグラウンドの Bash 呼び出しには、ランナー自身のタイムアウトが長くても、自動の 10 分上限がある。`&` でバックグラウンド化してタスクハンドルを失う方法では代替できない。
- Codex では、セッション ID を返す永続的な exec セッションでランチャーを実行し、そのハンドルを待機またはポーリングする。モデルが動いている間ずっと、1 回のフォアグラウンドツール呼び出しを開いたままにしない。

バックグラウンド処理を開始したら、他の作業枠の起動を続け、その後ハンドルから結果を回収する。ネイティブと外部の作業枠は、同じ並列展開フェーズで開始する。

ランナーとその事前確認に暗黙のタイムアウトはない。役割、モード、切りのよい数値から時間を勝手に決めない。実装作業は 90 分、あるいはそれ以上かかることがある。ユーザー、外部サービスの期限、計測に基づくタスクの契約が実際の上限を定める場合だけ `--timeout` を渡す。その値はモジュール読み込みや引数解析より前のラッパー開始時から計時し、セットアップ、事前確認、モデル実行、出力取得を通した 1 つの絶対期限とする。子ごとに新たな時間を与えるものではない。長い待機は、指定期限を短くせず、実行環境で安全な長さに分けて設定する。それ以外では、保持したバックグラウンドタスクやセッションのハンドルで生存を監視し、実行が死んだ証拠がある場合だけ手動で取り消す。取り消しはそのハンドル経由で行う。これによりランナーが SIGINT または SIGTERM を受け、動作中の子が残っていれば転送し、継承された出力パイプの待機をやめ、空の出力予約を除き、`cancelled` の証跡を書く。証跡は保存する。再試行は新しい試行として、固有の出力パスと証跡パスを新たに用意する。実行状態に変化がないことは脱落ではない。Claude のフォアグラウンドの 10 分上限を、正常な作業枠を終了する理由にしてはならない。

読み取り専用モードは、Claude ではプロジェクト設定だけと明示的なツール一覧を使う plan モード、Codex では読み取り専用サンドボックス、Grok では plan モードと `read-only` サンドボックスおよび読み取り向けツール一覧に対応する。Grok 組み込みの読み取り専用プロファイルは、自身の状態とシステムの一時ディレクトリを意図的に書き込み可能にしている。そのため、読み取り専用の Grok 作業枠には、`/tmp`、`/var/tmp`、ホストの一時ディレクトリ内の worktree ではなく、実際のチェックアウトを指定する。`isolated-write` は、Claude ではプロジェクト設定だけを使う `acceptEdits`、Codex では `workspace-write`、Grok では `acceptEdits` と `workspace` サンドボックスおよび書き込み可能なツール一覧に対応する。書き込み担当者には専用 worktree または出力ディレクトリだけを与える。主要なチェックアウトへ書き込み担当者を向けてはならない。

同時実行する外部作業枠には、それぞれ異なるプロンプト、出力、証跡のパスが必要である。ランチャーは出力と証跡のパスを排他的に予約し、上書きを拒否する。

## 完了と脱落

成功には次のすべてが必要である。

1. 終了ステータスが `0`。
2. 証跡のステータスが `complete`。
3. `modelVerified: true` かつ `modelEvidence: "provider-report"`、または Codex の証跡で `reportedModel: null`、`modelVerified: false`、`modelEvidence: "pinned-argv"` がそろっていること。Claude の別名 `fable` と `opus` では、プロバイダーが報告した具体的なモデルが要求した系列に属していなければならない。Codex 0.149.0 は正確な `--model` 引数を受け付けるが、JSONL ストリームでは実際に使われたモデルを報告しない。
4. 出力ファイルが空でないこと。

証跡には経過時間、CLI が公開する場合のトークン使用量、取得可能な場合の費用も含まれる。親の実行環境間の比較を証拠に基づかせるため、arena やレビューの成果物と一緒に保存する。

CLI の欠如、ログイン失敗、モデルの利用不可、明示的なタイムアウト、キャンセル、出力予約後に捕捉できるランチャーの失敗、子の非ゼロ終了、不正な形式の結果、モデル不一致は、いずれも証跡を伴う脱落である。記録し、呼び出し元スキルの既存の脱落方針を適用する。`cancelled` の証跡はランナーがシグナルを受けたことを示す。`signal` フィールドが非 null になるのは、まだ動いている直下の CLI 子プロセスへランナーがそのシグナルを送った場合だけである。子の終了後のパイプ回収を止めただけなら null のままである。その直下の子のさらに下に作られるプロセスはプロバイダー CLI が管理する。証跡はプロセスツリー全体の終了を保証しない。証跡を削除、上書きしない。親モデルで代替し、別プロバイダーで再試行し、外部記述子をネイティブモデルのスラッグとして解釈し直すことを禁じる。

ネイティブと外部の作業枠を同じ並列展開フェーズで開始し、全員を待ってから評価する。評価者は、担当者がまだ書き込んでいる候補のパスを読んではならない。
