### worktree とシミュレーターの整理

**ディスクと安全確認に責任を持つ。** マージ済みまたは放棄された Git worktree と古い iOS シミュレーターを削除し、容量を回収する。削除は取り消せないため、各手順で使用中のものや未コミットの作業を消さないよう確認する。

1. 現状を記録して監査する。`df -h /` を記録し、インストール済みプラグイン内の `skills/poteto-mode/scripts/worktree-audit.sh` を実行する。principle-build-the-lever に従う。このスクリプトはパスを手入力させず、`git worktree list` から読み取る。手入力の `myrepo-worktrees/x` では、実際には `.worktrees/myrepo/x` にあるものを見落とすためである。principle-encode-lessons-in-structure に従う。各 worktree を、容量、古さ、マージ状態、未コミット作業、PR の状態、その worktree に最後に触れた会話で分類し、扱いの区分を提案する。会話記録の走査は遅いのでバックグラウンドで実行する。
2. 区分は助言であり、許可ではない。判断の根拠となる実物は、ピン留めされた会話と進行中の会話である。principle-prove-it-works に従う。ユーザーまたは自分のセッション一覧からその集合を取得し、すべての候補と照合する。ツールが `safe` と判定した worktree をユーザーがピン留めしていたことがあるため、ピン留めの情報を優先する。
3. 削除前に利用状況を確かめる。`verify-recent-chat` の各行や、判断に迷うものについては、サブエージェントを並列に使って会話記録を読ませる。会話がピン留めされているか、進行中か、どの worktree に触れているかを報告させる。会話記録は大量なので principle-guard-the-context-window に従う。ピン留めされた会話は、バックグラウンドのサブエージェントを通じて、比較実験用や再現用の作業ツリーを隣接する worktree に作る。その名前がセッション一覧に出なくても使用中である。
4. 取り消せない損失の前で止まる。`wip:N` は、追跡対象ファイルに N 件の未コミット編集があることを示す。先に差分を見せ、判断を得る。クリーンな worktree はブランチから復元できるが、未コミット作業は失われるためである。`scratch:N` は未追跡の使い捨てファイルで、安全に削除できるが、ファイル名を示す。「自律性」に従い、クリーン、マージ済み、未使用のものは進める。`wip` と使用中のものは停止する。
5. 確認済みの集合を削除する。パスごとに `git worktree remove --force <path>` を実行する。無視対象のビルド成果物が残ってディレクトリが消えなければ、`rm -rf` で削除し、その後 `git worktree prune` を実行する。ブランチ参照は残るため、コミットは失われない。`df -h /` と一覧の再取得で確認する。
6. シミュレーターなどの容量も回収する。通常、次に効果が大きいのはシミュレーターである。XCTestDevices のクローンには `xcrun simctl --set testing delete all`、利用不能なものには `xcrun simctl delete unavailable` を使う。古いランタイムは `xcrun simctl runtime list` で確認し、`runtime delete <id>` で削除する。必要ならさらに、Xcode の `DerivedData` と `iOS DeviceSupport`、エディターのアプリケーションサポート用キャッシュ、`~/.claude/shell-snapshots/`、古い `~/.claude/projects/` の会話記録、pnpm、uv、brew、yarn のパッケージキャッシュを対象にする。**recall** スキルとセッションの引き継ぎが読む最近の会話記録は残す。ユーザーが保持を指定していないキャッシュだけを消す。

これは、コードレビューで誤りを拾う機会なしにユーザーの状態を削除する唯一の手順書である。そのため、上の安全確認がレビューの役割を担う。

**返信に含める内容：** 作業前後の `df -h /` と回収した容量、削除した worktree、見送った各対象の理由を 1 行ずつ。使用中ならどの会話が使っているか、または未コミット作業があることを示す。
